# 第五人格微博中文分词工具对比测试结果

日期：2026-11-19

项目：第五人格微博社交媒体大数据项目
测试平台：Windows 10 x64，Python 3.11.5，Intel64 Family 6 Model 140 Stepping 1，8 个逻辑处理器

## 结论摘要

**建议保留现有 jieba，不替换生产分词器。** jieba 加载现有领域词典后，343 个词典实体候选中有 332 个以整词保留（96.8%），17 个现有词表标记的攻击性表达全部以整词保留。cutword 加词典后的这两项比例相同，且在本次 110 条样本中更快，但绝对运行时间都很短；jieba 已集成现有别称归一、停用词和信号词处理，替换带来的维护和回归成本不值得。

本测试没有人工分词金标准，因此不计算 Precision、Recall 或 F1。表内完整率是基于现有词典的边界诊断指标，不代表全语料分词准确率，也不代表恶意言论分类。

## 测试方法

- 通过 SQLite 只读连接从现有研究数据库抽样，固定 SHA-256 种子和排序，共 110 条：微博 25 条、一级评论 45 条、楼中楼 40 条。
- 优先覆盖第五人格领域词、现有词表标记的攻击性别称、中英或数字混写、重复字符、标点和 Emoji；其余按固定顺序补齐。统计只使用聚合结果；本报告不含原文、用户名或数据库记录 ID。
- 每个工具和配置使用独立进程，先预热，再对同一组文本重复分词 5 次，报告中位耗时、条/秒和峰值进程 RSS。初始化分别记录首次加载和预热后的缓存初始化中位数。
- 磁盘占用为隔离环境安装包及必要运行依赖文件大小估算；工具包内模型文件计入包体积。RSS 由 psutil 采样。
- 领域词典按工具接口转换：jieba `add_word`；jiojio `cws_user_dict`；THULAC `user_dict`；cutword `custom_dict_path`（词和词频两列）。

## 兼容与词典适配

- **jieba：** 已在当前项目预处理流程中使用；通过 `add_word` 导入领域词表，改造成本最低。
- **pkuseg：** pkuseg 0.0.25 在 Python 3.11 / Windows x64 的源码构建需要 Microsoft Visual C++ 14.0+。补装 numpy、wheel 并关闭隔离构建后仍因缺少编译器失败；该版 PyPI Windows 预编译轮最高为 CPython 3.8，未生成 web 模型结果。[PyPI 发布文件](https://pypi.org/project/pkuseg/)
- **jiojio：** 支持 `cws_user_dict`，但本机峰值 RSS 约 2.0 GB，词表边界表现低于 jieba。
- **THULAC：** 支持每行一个词的 `user_dict`，本机安装包及必要依赖约 510 MB，峰值 RSS 约 1.7 GB。
- **cutword：** 支持 `custom_dict_path`，需要将词典转换成词和词频两列。包入口会导入可选 NER 模块并需要未声明的 torch；本次通过直接加载包内公开 Cutter 分词模块运行，未安装 PyTorch。

## 推荐

继续使用 jieba 及当前领域词典。与 cutword 相比，本次实体和攻击表达完整率相同；cutword 的 110 条样本耗时约 0.0065 秒，jieba 约 0.0243 秒，节省约 0.018 秒。现有样本工作量不构成运行瓶颈，而 cutword 会引入词典转换和预处理适配工作。jiojio 与 THULAC 的实测内存和磁盘占用较高，pkuseg 在当前 Python / Windows 环境无法运行。
